# Data Source & Simulation Design

This document explains the synthetic KOL dataset, market conversion parameters, and purchasing power adjustments used by the TikTok Shop KOL Matrix Optimizer.

---

## 1. KOL Schema (13 Fields)

The dataset is generated by `data/generator.py` and serialized to `data/sample_kols.json` and `data/influencers_mock.csv`. Each record contains the following fields:

| Field | Type | Range / Values | Description |
|-------|------|----------------|-------------|
| `id` | int | 1, 2, 3, … | Sequential unique identifier |
| `name` | str | `"KOL_{id}"` | Display name |
| `country` | str | MY / ID / TH / PH / SG / VN | Target Southeast Asian market |
| `category` | str | beauty / fashion / home / fmcg | Content category |
| `followers` | int | 1,000 – 5,000,000 | Total follower count |
| `engagement_rate` | float | 0.001 – 0.30 | Average engagement (likes + comments + shares) / views |
| `fit_score` | float | 0.30 – 1.00 | Cultural / brand fit score for the target market |
| `commission_rate` | float | 0.05 – 0.35 | TikTok Shop affiliate commission rate; tier-specific ranges (Mega 5–15%, Macro 12–22%, Micro 18–28%, Nano 25–35%) |
| `cost` | float | computed | Hiring cost = `commission_rate × _approx_expected_gmv()`; scales with creator quality (see §6.3) |
| `avg_views` | int | ≈ followers × 0.3 ± 5% | Average video views over the last 30 days |
| `avg_likes` | int | avg_views × engagement_rate | Average likes per video |
| `gender_ratio` | float | 0.00 – 1.00 | Female audience proportion (1 = 100% female) |
| `age_group` | str | 18-24 / 25-34 / 35+ | Dominant audience age bracket |

The `tier` field (Mega / Macro / Micro / Nano) is **derived from `followers`** at runtime by `engine.scoring.explainer.get_tier()`, not stored in the data file.

---

## 2. Why Synthetic Data?

The dataset is fully simulated rather than scraped from live platforms, for two reasons:

- **No public TikTok creator API.** TikTok does not provide an open developer endpoint for browsing creator pricing, demographics, or historical performance. Web scraping is rate-limited and prohibited under their Terms of Service.
- **Commercial sensitivity.** Real influencer hiring fees, audience demographics, and historical conversion data are covered by non-disclosure agreements between brands, agencies, and creators. Using synthetic data avoids any privacy or contractual risk while still allowing realistic algorithm evaluation.

The synthetic parameters are calibrated against publicly available industry reports on Southeast Asian influencer marketing to keep the distributions statistically plausible.

## 3. GMV Estimation Formula

### 3.1 Core Formula (v2)

```
GMV = sqrt(followers) × CTR(category, country) × CVR(category, country)
      × AOV(category, country) × purchasing_power(country)
      × engagement_factor × fit_factor × 200
```

where `engagement_factor = sqrt(engagement_rate / 0.132)` and `fit_factor = sqrt(fit_score / 0.650)`. Both use `sqrt(·)` for diminishing returns and are normalised to the dataset mean (ENG_BASE=0.132, FIT_BASE=0.650) so that the average KOL gets a quality multiplier of 1.0.

| Factor | Description |
|--------|-------------|
| `sqrt(followers)` | Diminishing-returns traction — 100× followers → 10× GMV |
| `CTR` | Click-through rate: fraction of viewers who click product link |
| `CVR` | Conversion rate: fraction of clicks that become purchases |
| `AOV` | Average order value in USD |
| `purchasing_power` | Country GDP/capita multiplier |
| `200` | Normalization constant (a 100K-follower beauty/MY KOL ≈ $7,900) |

### 3.2 Diminishing Returns Design

`sqrt(followers)` replaces the linear `followers × engagement × fit` formula. Rationale:

- A Mega KOL (3.2M followers) has only ≈5.7× the traction of a Micro KOL (100K), not 32×.
- This prevents the optimizer from always selecting the single biggest KOL, making mixed-tier portfolios (Mega + Micro + Nano) naturally emerge.
- Consistent with industry research showing follower count has sub-linear impact on sales conversion (Hughes et al., 2019; Leung et al., 2022).

## 6. Distribution Assumptions

### 6.1 Tier Distribution

The population follows a real-world long-tail distribution:

| Tier | Follower Range | Share | Reasoning |
|------|----------------|-------|-----------|
| **Nano** | 1,000 – 9,999 | 40% | High-volume, niche communities |
| **Micro** | 10,000 – 99,999 | 35% | High engagement, precise targeting |
| **Macro** | 100,000 – 999,999 | 20% | Broad reach with credibility |
| **Mega** | 1,000,000 – 5,000,000 | 5% | Celebrity tier, scarce supply |

Implementation in `generator.py`:
```python
tier_roll = random.uniform(0, 100)
if tier_roll < 40.0:  # Nano
elif tier_roll < 75.0:  # Micro
elif tier_roll < 95.0:  # Macro
else:  # Mega
```

### 6.2 Tier-Specific Engagement Rate Distribution

Engagement rate is assigned per-tier using distributions calibrated to real TikTok benchmarks (Brandwatch / TTS Vibes 2025). Each tier draws from a uniform base range, then applies ±15% per-creator noise:

```python
if followers < 10_000:        # Nano
    base = random.uniform(0.10, 0.30)   # real avg 17-18%
elif followers < 100_000:     # Micro
    base = random.uniform(0.04, 0.15)   # real avg 6-8%
elif followers < 1_000_000:   # Macro
    base = random.uniform(0.03, 0.10)   # real avg 5-7%
else:                          # Mega
    base = random.uniform(0.02, 0.08)   # real avg 4-6%
engagement_rate = max(0.001, min(0.30, base * random.uniform(0.85, 1.15)))
```

Generated distributions vs real benchmarks:

| Tier | Generated avg | Generated range | Real benchmark |
|------|--------------|-----------------|----------------|
| Nano | 19.6% | 10.0% – 30.0% | 17–18% |
| Micro | 9.8% | 4.2% – 17.1% | 6–8% |
| Macro | 7.1% | 3.3% – 10.5% | 5–7% |
| Mega | 5.7% | 2.9% – 8.2% | 4–6% |

**Why the previous formula failed:** The old formula `max(0.01, 100000/followers)` returned values ≥1.0 for any creator below 100K followers, causing `min(0.3, ...)` to cap all Nano and Micro creators at exactly 30%. This eliminated the tier-based differentiation that the optimizer relies on.

### 6.3 Cost Model (Commission-Rate Based)

Cost is **commission-rate based** rather than drawn from fixed tier ranges. This models the TikTok Shop affiliate structure where creators earn a percentage of the GMV they generate:

```python
# commission_rate drawn from four tier-specific ranges
if followers >= 1_000_000:                         # Mega
    commission_rate = random.uniform(0.05, 0.15)   # high volume → low rate
elif followers >= 100_000:                         # Macro
    commission_rate = random.uniform(0.12, 0.22)
elif followers >= 10_000:                          # Micro
    commission_rate = random.uniform(0.18, 0.28)
else:                                              # Nano
    commission_rate = random.uniform(0.25, 0.35)   # low volume → high rate

cost = commission_rate * approx_gmv
```

Commission rate ranges are calibrated against TikTok Shop SEA affiliate commission guidelines (TTS Vibes 2025, ContentGrip 2026).

Because `cost` scales with `expected_gmv`, a high-follower Macro KOL is both more valuable and more expensive than a low-follower Nano KOL in roughly the same proportion. This preserves the classic local-optimum trap — a Macro/Mega KOL can consume 60–80% of the budget while a portfolio of Micro+Nano KOLs at the same total cost achieves higher aggregate GMV through superior engagement multipliers. SA, GA, and TS are designed to discover and escape this trap.

### 6.4 Country, Category, Demographics

These fields are sampled uniformly at random:
- `country` ∈ {MY, ID, TH, PH, SG, VN}
- `category` ∈ {beauty, fashion, home, fmcg}
- `gender_ratio` ∈ U(0, 1)
- `age_group` ∈ {18-24, 25-34, 35+}

`fit_score` is sampled uniformly from [0.3, 1.0] — bounded above zero to model that any KOL pursued by a brand has at least minimal market alignment.

## 7. Reproducibility

The generator accepts a `seed` parameter (default `42`) and a `num` argument:

```bash
# Default 300 KOLs
python data/generator.py

# Custom pool size (edit the last line or call generate_kols(num=500) programmatically)
```

`generate_kols(num=300, seed=42)` always yields the same dataset, which is essential for fair algorithm comparison and for the reproducibility requirements of the project report.

## 9. Audience Overlap Penalty

The fitness function penalizes portfolios that select near-duplicate creators to encourage audience diversification. **Important:** the `/optimize` endpoint already filters by country AND category, so ALL KOLs in a given optimization run share those attributes. The overlap penalty therefore does NOT penalise same country/category (that would penalise every pair equally and drown the GMV signal). Instead, it penalises the remaining orthogonal diversity dimensions:

| Condition | Overlap Score |
|-----------|--------------|
| Similar follower range (within 50%) | +0.5 |
| Same age group | +0.3 |
| Same gender skew (both ≥70% female or both ≤30% female) | +0.2 |

Maximum overlap score = 1.0 (same follower tier + same age + same gender skew).

The penalty is applied as `overlap_score × 1,500` added to the fitness cost, which the optimizer minimizes. This directly discourages near-duplicate creators whose audiences are demographically indistinguishable.
